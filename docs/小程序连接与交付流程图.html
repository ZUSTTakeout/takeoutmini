校园美食街：从“无法连接服务器”到可交付

这张图把问题、修复、上线和交付串成一条线。截图里的“未连接”属于运行结果，不是操作指令。

检查 / 配置通过后继续需要准备当前阻塞

一、本地恢复连接

当前现象

微信开发者工具显示“无法连接服务器”

页面能打开，但店铺数据加载失败。说明前端在运行，接口没有回应。

检查 1

确认接口地址

项目默认请求 http://localhost:3000/api。它只对当前电脑有效，不能直接给别人使用。

检查 2

启动数据库和 API

需要 MySQL + NestJS API。项目提供 scripts/start-local.ps1，但当前电脑的 Docker 尚不可用。

准备依赖

安装并启动 Docker Desktop

启动后再次运行本地启动脚本；如果不使用 Docker，就要单独安装 MySQL 并配置连接参数。

验证

打开健康检查地址

访问 http://127.0.0.1:3000/api/health/live。能返回成功，才说明 API 已启动。

验证

重新编译并导入微信开发者工具

构建 apps/miniapp/dist/build/mp-weixin，然后重新编译、刷新预览。

二、比赛 / 校方交付

先做演示版

完成核心功能验收

逐项测试：登录、店铺、商品、购物车、下单、订单取消、商户订单处理。

上线准备

部署真实后端和数据库

把 API 和 MySQL 部署到服务器，不能继续使用 localhost。准备固定服务器和备份策略。

微信配置

改成 HTTPS 域名并配置合法域名

例如 https://你的域名/api。在微信公众平台配置 request 合法域名。

账号配置

填写真实 AppID / AppSecret

当前项目的微信配置为空，开发登录只适合本地演示，正式交付前必须完成真实登录联调。

交付方式

上传体验版给评委或老师

微信开发者工具上传代码，在公众平台生成体验版二维码，供比赛和校方试用。

交付材料

同时提交完整资料包

小程序源码、后端源码、数据库说明、部署说明、测试账号、功能说明、演示视频和体验版二维码。

现在最先做的事：先解决本地 API 启动问题；本地能稳定显示店铺和商品后，再做服务器部署和微信正式配置。只把源码压缩包发出去，别人无法直接运行这个小程序。

依据当前项目状态整理：API 端口 3000 未监听；本地配置默认使用 localhost；Docker 当前不可用；正式环境还需要 HTTPS、合法域名和真实微信配置。
